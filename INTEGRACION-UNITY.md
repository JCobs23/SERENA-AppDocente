# Integración del flujo docente con Unity

La app web conserva la estructura React/Vite del trabajo del equipo. El flujo es login → bienvenida → catálogo → sala de espera con código.

- React implementa el login en `frontend/src/components/LoginScreen.tsx`; `App.tsx` mantiene la navegación existente.
- Al elegir la narrativa se crea un codigo en ASP.NET Core (POST /api/sessions). La sala docente abre un WebSocket autenticado en /api/sessions/{code}/stream, recibe una instantanea inicial y los cambios en vivo; GET /api/sessions/{code}/students queda como consulta de respaldo.
- Unity valida el codigo con GET /api/sessions/{code} y registra nombre e identificador persistente con POST /api/sessions/{code}/students. Envia un latido cada 5 segundos a POST /api/sessions/{code}/students/{studentId}/heartbeat. Si pasan 15 segundos sin latidos, la API marca al estudiante desconectado; al volver con el mismo ID, lo marca reconectado. POST /api/sessions/{code}/students/{studentId}/leave registra una salida explicita.
- Unity consulta GET /api/sessions/{code} periódicamente mientras el estudiante está en la experiencia. Cuando `narrativeStarted` cambia de `true` a `false`, el listener detiene el video o etapa, limpia el estado local del estudiante y carga `1_IngresoCodigo`. El botón docente “Volver a escoger capítulos” hace POST /api/sessions/{code}/reset antes de salir; el reinicio también limpia el indicador de introducción completada para permitir iniciar después. Para desplegar el cambio en una tablet, genera e instala un build Android nuevo.
- **Omitir introducción** es una acción docente autenticada (`POST /api/sessions/{code}/skip-intro`). La API marca como completada la introducción de los estudiantes conectados y avanza a la etapa 1; Unity detecta ese estado y detiene el video. La app del estudiante no ofrece un control para omitirla.
- La escena `3_Narrativa` incluye el objeto `NarrativeStageView`, que recibe del listener persistente la etapa y el estado multimedia (`mediaPaused`, `mediaPositionSeconds`, `mediaRevision`, `mediaCommand`). Al entrar en la etapa 1, reproduce `Assets/StreamingAssets/SerenaNarrativa.mp4` en la tablet con `VideoPlayer` y presenta el titulo y la descripcion en una franja legible. Los controles docentes `POST /api/sessions/{code}/media` envian la accion multimedia y su revision. Unity aplica pausa/reanudacion y saltos de cinco segundos contra el reloj local del reproductor para evitar desfases por descargar y preparar el video. Cada orden se aplica una sola vez al llegar por la consulta de estado. Al recibir `loopPointReached`, el reproductor queda marcado como finalizado y no vuelve a ejecutar Play hasta una nueva orden de reinicio al entrar en Etapa 1. La proyeccion conserva la tarjeta de etapa y los controles; no reproduce este video. Al cambiar scripts o el archivo, vuelve a generar e instalar el build Android.
- `GET /api/sessions/{code}` publica tambien `mediaPaused`, `mediaPositionSeconds`, `mediaRevision` y `mediaCommand` en el estado de la sesion. La proyeccion usa estos campos para mantener el estado de los botones; Unity usa `mediaCommand` y `mediaRevision` para ejecutar la accion sobre el video local.
- El backend Node/Socket.IO se conserva para los eventos existentes del equipo. La presencia usa WebSocket directo con Serena.Api.

Para instrucciones de instalación y ejecución, consulta `GUIA-USO.md`. El login requiere HTTPS y el registro de estudiantes por Unity aún usa HTTP para la demostración local; no usar con datos reales hasta asegurar esa comunicación.
